Phase 1 — Fondations
Par où j'ai commencé
Avant d'écrire la moindre ligne de code, il faut poser les décisions irréversibles. C'est ce qui rend tout le reste cohérent.
Principes non négociables
Définir 4 valeurs avant tout : souveraineté numérique, accessibilité WCAG 2.1 AA, auditabilité totale, dernier mot humain. Ces principes ne changent jamais.
Architecture à 3 niveaux de tokens
Primitif → Sémantique → Composant. La décision la plus structurante : découpler les valeurs physiques des intentions UX. Codifiée dans ADR-001.
Premier ADR
Documenter la première décision de design dans un fichier versionné. Ce fichier devient la mémoire du système. Tout commence ici.

Règle fondatrice : aucun token n'est utilisé directement sans passer par la couche sémantique. Cette contrainte force la cohérence à grande échelle et permet aux agents de comprendre le "pourquoi" de chaque décision.

Phase 2 — Construction
Ce qu'il a fallu mettre en place
Les 4 piliers qui permettent au système de fonctionner de façon autonome tout en restant sous contrôle humain.
ADRs — Mémoire institutionnelle
Architecture Decision Records : chaque décision documentée (quoi, pourquoi, alternatives rejetées, conséquences). Les agents lisent les ADRs avant d'agir. Aujourd'hui : 58 ADRs actifs.
  • Versionnés dans Git — jamais supprimés
  • Marqués "remplacé" si dépassés
  • Format structuré lisible par les humains et les agents
AGENTS.md — La constitution des agents
Le premier fichier que tout agent doit lire avant d'agir dans le dépôt. Définit ce qui est autorisé, ce qui est interdit, comment escalader, et comment demander une révision humaine.
  • Règles immuables inscrites dans le code
  • Pas de contournement possible
  • Mis à jour uniquement via PR approuvée par un humain
Figma synchronisé avec les tokens
Les tokens sont la source de vérité. Figma est un miroir — pas l'inverse. Toute dérive visuelle dans Figma est détectée automatiquement par l'Agent Design.
  • 36 échelles de couleur synchronisées
  • Composants liés aux tokens sémantiques
  • Détection automatique des détachements
Pipeline CI/CD avec portes humaines
Chaque PR passe par des vérifications automatiques. Aucune modification ne peut atteindre la branche principale sans approbation humaine explicite.
  • Tests WCAG 2.1 AA automatiques
  • Régression visuelle bloquante
  • Lint de tokens (aucune valeur en dur)

Phase 3 — Opérations
Les 4 agents au travail
Chaque agent a un rôle précis, des permissions explicites et une limite infranchissable : aucun ne peut approuver ses propres modifications.
Agent Design
Surveille Figma en continu. Détecte les composants détachés du système, les tokens manquants, les espacements non conformes.
Surveille
Agent Code
Détecte les valeurs codées en dur dans le code. Génère des correctifs, ouvre des PR avec description complète.
Corrige
Agent QA
Tests WCAG 2.1 AA automatiques à chaque changement. Détecte les régressions visuelles. Bloque tout changement non conforme.
Bloque
Agent Docs
Génère automatiquement les notes de mise à jour, guides de migration, et maintient la documentation synchronisée avec le code.
Génère

Règle absolue : aucun agent ne peut fusionner ses propres modifications sur la branche principale. Toute modification touchant les tokens sémantiques ou de composant déclenche automatiquement une escalade vers un humain.

Qualité continue
Comment s'assurer de la qualité
La qualité n'est pas une étape finale — c'est une propriété structurelle du système, vérifiée à chaque changement.
Accessibilité par construction
Chaque composant embarque ses règles WCAG 2.1 AA. 21 critères vérifiés automatiquement avant toute livraison. Aucun contournement possible.
Régression visuelle bloquante
Les captures visuelles sont comparées à chaque PR. Toute déviation non intentionnelle bloque la fusion. L'historique visuel est versionnée.
Zéro valeur codée en dur
Le lint de tokens détecte toute couleur hex, espacement px ou taille en dur dans le code. Ces erreurs bloquent la PR — sans exception.
Traçabilité complète
Chaque décision, correction et déploiement est versionnée dans Git. On peut répondre à "pourquoi" pour n'importe quel état du système.
Propagation automatique
Un changement primitif se propage automatiquement vers le sémantique et le composant. Les dérives sont signalées en temps réel, pas découvertes en UAT.
Portes humaines immuables
3 points de contrôle humain dans le pipeline. Décision UX, révision PR, déploiement. Ces portes sont inscrites dans le code — pas dans une politique.

Gouvernance · Autonomie progressive
Les 4 niveaux de confiance des agents
L'autonomie évolue selon la nature de la tâche. La porte humaine reste toujours disponible — et toujours prioritaire.
Niveau 1
Propose
Profil : stagiaire supervisé
Suggère des corrections, génère des rapports. Rien ne se produit sans approbation humaine explicite.
Niveau 2
Corrige
Profil : junior encadré
Applique des corrections mineures préapprouvées — tokens dépréciés, nommage non conforme. L'humain révise après.
Niveau 3
Soumet
Profil : intermédiaire
Crée des demandes de révision complètes. Un humain valide et approuve avant toute intégration.
Niveau 4
Déploie
Profil : senior — cas très limités
Autonomie maximale uniquement pour la documentation et les changelogs. Jamais pour les tokens ou les composants.

Phase 4 — Scalabilité
Comment ça peut grandir
Le système est conçu pour scaler sans fragilité — plus d'équipes, plus de composants, plus d'agents — sans perdre la cohérence ni le contrôle.
Nouveaux composants sans règles nouvelles
Tout nouveau composant hérite automatiquement des tokens et des règles existantes. Pas besoin de redéfinir les principes — ils s'appliquent par construction.
Nouvelles équipes sans formation longue
Les ADRs expliquent le "pourquoi". AGENTS.md explique les règles. Une nouvelle équipe peut contribuer en lisant le système — pas en demandant aux experts.
Nouveaux agents sans réécriture
L'architecture de rôles permet d'ajouter des agents spécialisés (i18n, performance, sécurité) sans modifier les agents existants ni les tokens.
Multi-produit depuis une seule source
Les tokens sémantiques peuvent alimenter plusieurs produits simultanément. Un changement de marque se propage dans tous les produits en une seule PR.
Zéro vendor lock-in
Code source public, hébergé sur GitHub, aucune dépendance propriétaire non maîtrisée. Le système reste sous contrôle organisationnel complet.
Métriques qui évoluent avec le système
714 tokens, 58 ADRs, 36 échelles, 21 critères WCAG — ces chiffres croissent avec le système. Chaque ajout est tracé, documenté, et versionnée.
